Observations (measured)
--------------------------------------------------------------------
- COPY into raw is fast; most of the per-file time is the SQL rules in
  data_quality.sql (safe-cast functions run per value, NOT EXISTS lookups).
- Orders are slower per row than items: more rules, more columns to cast.
- The checkpoint makes a no-change rerun cost only file hashing + metrics.

Estimates (NOT measured) - see docs/architecture.md, Performance section
--------------------------------------------------------------------
- Rate is roughly linear in rows; the full public dataset is ~4x larger
  (9 MB orders + 7.5 MB items vs ~4 MB here), so an estimated ~40 s.
- At millions of rows per batch the first bottleneck would be the per-row
  PL/pgSQL safe casts; replacing them with regex checks and set-based
  casts, and partitioning raw/facts by month, are the first steps.
